# Markdown 编辑器 AI、生成朗读与分屏同步计划

日期：2026-07-21
状态：已完成

## 1. 目标

本轮统一收口 Markdown 编辑器的三条交互链：

1. 润色、翻译、总结从请求开始到结果应用/取消期间冻结文稿内容，消除同一任务里的异步版本差异。
2. 把“朗读文稿”重构为“生成朗读”成品流程：先生成一个持久音频，再由成品弹窗提供立即朗读、打开所在目录、重新生成与关闭。
3. 左右并排分屏默认同步滚动，使用源码行与 Markdown 块锚点双向映射；上下堆叠的小屏布局自动暂停同步。

三项改动共用同一原则：任务状态、持久资产、弹窗开关和临时播放/滚动状态分别拥有，不用单个布尔值或组件是否挂载猜测真实状态。

## 2. AI 文稿事务

### 状态与所有权

- 同一个 draft 在 Rust 进程内任一时刻只允许一个运行中的 AI 任务；不同 draft 仍可并行。
- 前端在用户点击 AI 操作时同步取得本地启动锁，不等待 Rust 事件返回后才禁用界面。
- 文稿 revision 同时包含标题和正文。Rust task lease 仍是跨 WebView 的最终所有权，旧 lease 和旧 revision 不能覆盖新文稿。
- 锁定持续到成功结果被应用或取消；失败结果不继续锁定正文。

### 锁定范围

- 锁定：标题、CodeMirror 输入、Markdown 格式工具栏、场景预设、打开文件、清空退出、连续语音追加开关。
- 保留：滚动、选择、复制、编辑/预览/分屏切换、保存、导出、关闭窗口。
- CodeMirror 使用原生 `readOnly`/`editable` Compartment 动态切换，不加遮罩，不重建编辑器。
- AI 期间到达的连续语音结果进入内存队列；结果应用或取消后按到达顺序追加一次，不能静默丢弃，也不能提前改变 AI 请求快照。

## 3. 生成朗读成品

### 主状态机

| 资产/任务状态                | 主按钮        | 点击行为                           |
| ---------------------------- | ------------- | ---------------------------------- |
| 当前文稿没有匹配音频         | `生成朗读`    | 立即冻结文本/声音快照并开始生成    |
| 当前快照正在生成             | `生成中 n/m…` | 不发起第二个任务                   |
| 当前快照已有成品             | `生成完毕`    | 重新打开同一个成品弹窗，不重复生成 |
| 成品正在播放                 | `朗读中…`     | 打开成品/停止播放控制              |
| 文稿或声音已变化、仅有旧成品 | `重新生成`    | 为当前快照生成新成品               |
| 成品文件被移动或删除         | `生成朗读`    | 清除当前匹配并给出可读提示         |

关闭弹窗、播放结束或打开目录都不改变“音频已经生成”的事实。生成成功弹窗包含“立即朗读”“打开所在文件夹”“重新生成”“关闭”；按钮旁的“朗读音频”目录入口始终可用，首次使用时目录可能为空，切换文稿后也不会失去历史成品入口。

### 原生生成与持久化

- 生成编排放在 Rust，不由 React 循环串联请求；编辑器关闭/重新挂载后任务和结果仍可查询。
- 复用进程级 TTS owner，使首页朗读、设置试听、Markdown 生成和成品播放互斥；生成任务使用进程所有者，不绑定已关闭的 WebView。
- 仍按既有 1200 字语义边界分段，但每段显式请求 WAV。Rust 解析 RIFF/WAVE，要求 PCM `fmt` 一致，只拼接 `data` 并重建一个合法 WAV；禁止直接拼接 MP3 字节。
- 最终目录固定为用户“文档/EcholIKE/朗读音频”。文件名使用清理后的标题、生成时间和唯一 ID；旧成品不覆盖、不自动删除。
- 同目录唯一 `.part` 文件完成 `write/flush/sync` 后原子改名；失败只清理由当前任务创建的临时文件。
- `echo.db` 新增独立 artifact 表，只记录 artifact ID、draft ID、请求指纹、声音、受控文件名、时间和字节数；不保存正文、Token、任意绝对路径或音频正文。
- 播放时 Rust 按 artifact ID 重新校验数据库记录和受控目录，再通过 raw IPC 读取音频为 blob；不启用全局文件协议，不接受前端传入任意路径。
- 打开目录/定位文件同样只接受 artifact ID 或固定目录命令，由 Rust 构造平台命令。

### 异常边界

- 不做音频设备预检。播放失败不否定已生成资产，提示用户打开目录使用其他播放器。
- 同一文稿重复点击、跨窗口并发、旧进度或旧完成事件都不得创建第二个任务或覆盖更新的状态。
- 应用重启后运行态归零；数据库中仍存在且文件可读的成品恢复为“生成完毕”。文件缺失时安全回到待生成状态，历史目录仍可打开。

## 4. 分屏同步滚动

- Markdown parser 为顶层块生成 `startLine/endLine` source map；标题、段落、列表、表格、引用、代码块、分隔线和对齐块都保留源码范围。
- CodeMirror 通过 `lineBlockAtHeight`/`lineBlockAt` 暴露连续源码行坐标，不查询会被虚拟化的 `.cm-line` DOM。
- 预览按相邻块锚点做局部分段插值，首尾显式对齐；禁止使用两侧总高度百分比。
- Shell 是唯一协调者：当前发生 wheel/pointer/touch/keyboard 的 pane 获得控制权；程序化滚动带 generation/suppression 标记，不反向反馈。
- 每个方向每帧最多写入一次，使用最新滚动位置；模式、草稿或组件变化时取消旧 rAF 和抑制状态。
- 偏好键为 `echolike.markdownEditor.scrollSync.v1`，默认开启。只有用户点击开关才写入；小屏上下堆叠只临时停用，不覆盖偏好。
- 是否真正并排由两个 pane 的布局与 `ResizeObserver` 判断，不用 `window.innerWidth` 猜测容器。

## 5. 验证门禁

### 前端

- AI：立即锁、恢复中的任务锁、成功待处理锁、结果取消/应用解锁、标题/正文 revision、语音结果排队、跨 remount。
- 朗读：五种按钮状态、弹窗取消不丢资产、播放结束回到“生成完毕”、目录入口、文稿变化后的旧资产、重启查询与旧事件隔离。
- 滚动：块 source map、双向局部插值、顶部/底部、rAF 合并、反馈抑制、用户夺回控制权、小屏停用与偏好恢复。
- Tauri bridge：所有新命令的字段、raw 音频返回与 artifact ID 边界。

### Rust

- 同 draft AI 互斥、不同 draft 并行、任务完成后可启动下一项、旧 lease 隔离。
- WAV 解析/合并、格式不一致/损坏/空 data 拒绝、原子落盘失败清理、Windows 文件名清理。
- artifact 表写入/查询、精确指纹恢复、旧成品保留、文件缺失、任意路径拒绝。
- 生成任务并发、进度与旧 lease、TTS owner 生成/播放互斥、窗口销毁不终止进程所有的生成任务。

完成后运行定向 Vitest/Rust 测试、TypeScript/Vite build、ESLint、Prettier、Rustfmt 与 `git diff --check`。本轮不改版本、不构建或发布 OTA、不部署后端，也不重启任何长期服务。
